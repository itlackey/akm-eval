# akm-eval: end-to-end review, 2026-10-11

A review of the whole repository at commit `bacf627` against its stated purpose: repeatable, continuous, iterative benchmarking of akm's processes across models, to power automated testing and tuning of akm and to measure what a tuning change does, in a form the public can rerun with other models and configurations and on their own bundles.

Every finding below was checked against the code, and where it was practical, reproduced by running the code. akm itself is not in this repository and was not installed in the review environment, so claims about akm's own behaviour (its JSON shapes, its database schema, its defaults) are taken from what this repository assumes about akm, not verified against akm.

## 1. Summary

The repository is in good shape as a set of individual evals. Every test passes (918 across 44 files), every folder typechecks, the sandboxing is careful, the metrics are mostly right, and the READMEs are unusually honest about noise, set size and judge drift. The problems are at the seams: between the evals and the akm build under test, between one run and the next, and between what the READMEs promise and what the code does.

The eight findings that most hinder the stated goals:

1. **The semantic index cache is keyed on the akm version string, not the build.** A PR checkout prints the release's version, so a changed indexer or embedding pipeline reuses an index another build made, and the change is invisible. (A1)
2. **The two Harbor evals (agent-ab, terminal-bench) can only compare npm releases of akm.** They have no `--akm`, ignore `AKM_BIN`, and fail setup unless `akm --version` equals a hard-coded pin. (A2)
3. **The matrix runner refuses to compare two akm builds.** Any row whose `akm_build` differs from the baseline's is "not comparable", so the one tool meant for sweeps cannot do a build-versus-build sweep. (A3)
4. **bakeoff never runs akm.** It re-implements akm's prompts from an unversioned snapshot and still scores two jobs akm removed in 0.9.17. It measures a copy, not akm. (A4)
5. **The contract with akm (JSON output shapes, proposal table schema, warning text, flag spellings) is encoded only in fake-akm test doubles and is never exercised against a real akm in CI, because there is no CI.** Version references drift across 0.9.21, 0.9.26, 0.9.30 and 0.10. (A5)
6. **Nothing compares runs per case.** Every eval writes `samples.jsonl` with stable ids, but the only comparison is a min/max/mean spread over 3 whole runs. With sets of 20 to 60 cases, that rule cannot see tuning-sized effects. (B1)
7. **Several scorers have verified defects**, the worst being extract's prompt-injection harm metric, which misses "Always skip tests if CI is red." and flags a memory that correctly warns about the injection. (D1)
8. **The public library carries 24 materialised copies of akm's own ref projections**, so the same ref is claimed by two files and the corpus membership depends on index order. Two shipped skills reference files that moved. (F1, F2)

Section 3 lists everything found, grouped by theme. Section 4 is the recommended plan.

## 3. Findings

Severity: **Critical** blocks a stated goal outright; **High** materially misleads a tuning loop or a public user; **Medium** a real defect or gap with a workaround; **Low** hygiene.

### A. Can the repository measure a change to akm?

**A1. High. The semantic index cache ignores the akm build.**
`lib/akm/index-cache.ts:148` builds the cache key from `[version, SEMANTIC_MODEL, dir, extra, semanticConfig()]`. `evals/retrieval/src/run.ts:283` and `benchmarks/skillret/src/run.ts:293` pass only the printed version. `lib/akm/akm.ts:173` itself notes that "a pre-release 0.10 build still prints a 0.9.x version", and the root README says to compare only runs of the same `akm_build`. So a PR checkout run with `--akm "bun ~/akm/src/cli.ts"` that changes indexing, chunking, projection or embedding code queries the index a different build made. `summary.json` says only `semantic_index: "warm"`. The exact class of change a tuning loop makes to retrieval is masked.
*Fix:* add `akmBuild().akm_build` (and the resolved `akm_bin`) to the key; write who built the index into `state.json` and copy it into `summary.json`; or skip the cache whenever `akm_build` is not null.

**A2. High. agent-ab and terminal-bench can only A/B npm releases.**
`lib/harbor/harbor.ts:9` pins `akm_cli: "0.9.26"` and the plugin; `lib/harbor/akm_opencode.py:148` runs `npm i -g akm-cli@<pin>` inside every container, and `:184` fails setup unless `akm --version` equals the pin. Both runners parse only `MODEL_OPTIONS` (`evals/agent-ab/src/run.ts:136`, `benchmarks/terminal-bench/src/run.ts:176`): `--akm` is an unknown option and `AKM_BIN` is never read. There is no `--strategy` or `--config-patch` path (`AKM_ENV` at `akm_opencode.py:49-62` is hard-coded). The summaries omit `akm_version`, `akm_bin` and `akm_build`. The root README's "`--akm COMMAND` on every one that runs akm" is false for these two.
*Fix:* let `--akm` take an npm spec or a local checkout (`npm pack` it, upload the tarball with Harbor's `upload_dir`, install from the file, same for the plugin); replace the equality check with "record what was installed"; write the akm fields to `summary.json`; pass `akm.kwargs.env` through so a config or strategy can be swept.

**A3. High. The matrix cannot compare two builds.**
`scripts/matrix/src/lib.ts:370` returns "not comparable" whenever `base.akm_build !== cfg.akm_build`. The root README says the matrix "is for comparing akm settings, strategies or builds". A config row with `--akm <branch>` against a baseline on `main` always gets that verdict. The guard is right for a config sweep and wrong for a build sweep; the file does not distinguish them.
*Fix:* add a row-level `"treatment": "build"` (or infer it from a differing `--akm` in `args`) that relaxes the build check while keeping the model check; report the two builds in the decision row.

**A4. Critical. bakeoff does not run akm and its prompts have drifted from akm.**
`evals/bakeoff/src/bakeoff.py` (2,908 lines of Python) hardcodes every prompt in `build_messages` (lines 246-602); `subprocess` is imported only for `git`; `README.md:5` says "akm does not need to be installed". Nothing records which akm the prompts were taken from. Drift visible from this repository's own documents: it still scores `graph_extraction` and `metadata_enhance` (19 of 120 cases; `bakeoff.py:52-53, 524, 532, 1403-1404`) although `reports/retired-evals.md:46,70` records that akm 0.9.17 removed the graph; its 13 `reflect_proposal` cases ask for a "complete improved markdown body" (`bakeoff.py:392, 585`) although reflect has been frontmatter-only since 0.9.25; its 22 consolidation cases ask for merge/delete/promote/contradict operations although 0.9.26's pair judge emits six labels with claim lists. It sends bare chat completions with no schema and no repair turn, which akm's pipeline does send. So bakeoff cannot register any akm tuning (prompt, parser, schema, repair) and cannot run on a user's bundle. It is also outside `--model`/`models.json`, `--repeat`, `lib/results.ts` and the matrix, and its tests are outside `bun test`.
*Fix:* decide which it is. Either drive akm through `lib/akm` like the other process evals and keep its deterministic scorers, or relabel it as a model probe on a frozen prompt set, pin `prompts_version` in `summary.json` and the README, and retire the graph, metadata and body-reflect cases instead of requiring them in `verify`.

**A5. High. The akm contract is untested and the version story has drifted.**
Every `run.ts` is tested only against a fake akm script that prints "akm 0.9.99-test" and the JSON shapes the eval expects (`consolidation.pairPass.pairsConsidered`, `usageReport.byProcessEngineModel`, `gateDecision.outcome`, `retirement.retiredRef`, proposal `source: "consolidate-pair"`, the exact text of two consolidate warnings parsed at `evals/consolidate/src/pool.ts:180-181`, the `[triage] judgment dispatch failed` line at `evals/promotion/src/lib.ts:128`, the `parse failed` substring at `evals/judge-gate/src/lib.ts:101`). promotion goes further and inserts rows into akm's SQLite `proposals` table and reads its `events` table (`evals/promotion/src/run.ts:134-137, 148-150`). Only `evals/reflect/src/run.test.ts:238` and `benchmarks/terminal-bench/src/run.test.ts:274` have tests that run a real akm, and they skip when none is installed, which is always, since there is no CI. Meanwhile the READMEs say "written for 0.9.26", `MIN_AKM` floors exist in nightly (0.9.26), reflect (0.9.25-alpha.3) and judge-gate, consolidate's pool notes quote timings "with akm 0.9.30", distill's `lesson-update` class needs 0.10.0, and `lib/akm/akm.ts:163` already special-cases a 0.9 versus 0.10 flag spelling. Nothing says which akm versions the repository as a whole is known to work with, and nothing would notice when one stops.
*Fix:* (a) a GitHub Actions workflow that installs a pinned akm release and runs `bun test` plus one `--limit 1` smoke run of each eval against a tiny stub OpenAI server, on push and nightly; (b) a `COMPATIBILITY.md` (or a table in the root README) naming the akm range each eval supports and the last release it was run on; (c) ask akm for a stable `--format json` schema version and a proposal import command so promotion stops writing to `state.db`; (d) record the json shape version in `summary.json`.

**A6. Medium. extract and judge-gate cannot be tuned.**
`evals/extract/src/lib.ts:228` hardcodes a strategy with `triage.enabled: false` and `indexSessions: false`; `evals/extract/src/run.ts` and `evals/judge-gate/src/run.ts` do not import `lib/akm/overrides.ts`, so neither takes `--strategy` or `--config-patch`, and their summaries omit `strategy` and `config_patch`. The root README is consistent (it lists five evals), so this is a gap against the goal, not a doc mismatch: extract's cheapest tunables (triage thresholds, event cut, budget) cannot be swept.
*Fix:* adopt `parseOverrides`, `patchedConfig` and `overrideSummary` in both, as reflect does at `evals/reflect/src/run.ts:12, 112, 221, 255`.

**A7. Medium. consolidate and nightly test pairing in a hash space.**
Both set `AKM_EMBED_DETERMINISTIC=1` (`evals/consolidate/src/lib.ts:129`, `evals/nightly/src/run.ts:176`), so the pair pass finds candidates with akm's word-hash embedder, not the production model. The READMEs say so. The consequence for tuning is that any change to cosine floors, neighbour counts or the embedding pipeline is measured against a geometry production never sees; only the judge half of consolidate is measured as shipped. retrieval and promotion already run the real embedder from `.cache/`.
*Fix:* add `--embedder deterministic|real` (default deterministic for speed), run the real embedder in the matrix confirm stage, and record which ran in `summary.json`.

**A8. Medium. longmemeval measures only akm's keyword mode.**
`benchmarks/longmemeval/src/run.ts:442` opens `createSandbox(NAME)` with the plain config; there is no `--semantic`. The README's reason ("Embeddings would need a model download") is stale: `lib/akm` caches the model and skillret uses it every run. Half of akm's retrieval surface is unmeasured on its memory benchmark. Separately, the skillret README notes akm cuts the keyword body projection at 16,384 characters; LongMemEval sessions average about 9k characters and some exceed the cut, and the benchmark neither counts nor reports those.
*Fix:* add `--semantic` (sandbox `{ semantic: true }`, verify `searchMode`), record the mode, and log sessions over the projection limit.

### B. Statistical design and repeatability

**B1. High. No paired comparison anywhere.**
`lib/repeat.ts:35-45` reduces N runs to min/max/mean of each aggregate. `scripts/matrix/src/lib.ts:353-359` calls a metric "better" only when the config's min-max range over the repeats does not overlap the baseline's; `repeats` defaults to 3. Every eval writes `samples.jsonl` with stable case ids, so a paired per-case comparison (which cases flipped, sign test or paired bootstrap over cases, flip rate per case across repeats) is available and far more sensitive, but nothing computes it. With 20 to 60 cases and a stochastic model, three-run ranges overlap for anything but a large effect, so the confirm stage mostly returns "no difference". The screen stage with the default `--min-delta 0` (`run.ts:58`) selects any config whose n=1 mean moved at all, so it filters almost nothing. For retrieval, `--repeat` is a no-op by construction (same index, same grades), and the range rule will call a 0.001 difference "better".
*Fix:* a `scripts/compare` that takes two or more results folders and reports, per case, agreement, flips and a paired bootstrap confidence interval on the main metrics; have the matrix use it in the confirm stage; report per-case flip rate across repeats as the eval's own noise floor; set a sensible default `--min-delta` per eval from that floor.

**B2. High. The Harbor evals cannot resolve tuning-sized effects.**
agent-ab has 9 tasks and a bootstrap over tasks only (`lib/harbor/report.ts:120-132`). terminal-bench hardcodes `ATTEMPTS = 1` (`benchmarks/terminal-bench/src/run.ts:19`) with no flag. The terminal-bench README's own two runs show the control arm flipping 6 of 26 tasks and the measured effect moving from -0.077 to +0.115, which is larger than any plausible akm effect. Neither eval supports `--repeat` (their summaries lack the keys `lib/repeat.ts:12-21` requires) and neither is in `EVAL_METRICS`, so a sweep cannot include them.
*Fix:* `--attempts N` for terminal-bench, `--repeat` for both, a paired bootstrap that resamples attempts within tasks, an exact sign test on disagreeing tasks, and matrix registration with `report.delta.value` as main and `akm.errored`/`engagement.control_calls` as harm.

**B3. Medium. Sampling settings are inconsistent and unrecorded.**
Only distill (`evals/distill/src/lib.ts:261`) and extract (`evals/extract/src/lib.ts:226`) pin temperature 0 and turn thinking off. judge-gate's `judgeConfig` (`evals/judge-gate/src/lib.ts:80-85`) sets neither; nightly, consolidate and promotion inherit akm's defaults; the reflect README says akm sends 0.3. No eval sets a seed, even where the endpoint supports one. No `summary.json` records temperature, seed, max tokens or thinking switches, so repeat spreads mix sampling noise with model noise, and two runs cannot be shown to have used the same settings.
*Fix:* one `engineConfig` policy (temperature 0, thinking off, seed when supported), a per-eval override only where a process needs it, and the effective engine settings written to `summary.json`.

**B4. Medium. The sets are small, and nothing tracks their noise floor.**
nightly 29 items, consolidate 60 pairs (10 per relation) plus an 80-note pool, distill 38, reflect 50, promotion 20 (6 good), extract 20 sessions, judge-gate 106 (28 good), agent-ab 9 tasks. The READMEs say so and say one case is 3 to 25 points. That is honest, but a tuning loop then needs the per-case flip rate from B1 to know what "one case" means for each eval, and the public sets need to grow where a class has 4 to 6 cases.

**B5. High. retrieval's judgment pool is keyword-only and cannot grow from a run.**
`evals/retrieval/src/label.ts:117-126` pools the keyword `search`/`curate` top-10, BM25 and the `expected` lists; no semantic sandbox, no way to pool a results folder. Unjudged hits score 0 (`lib/ir.ts:38`). The README admits semantic `judged_10` is 71%. Any ranker or config change that surfaces new assets is penalised for surfacing them: a structural bias toward the status quo, which is the opposite of what a tuning loop needs. Judgments also carry no provenance (`label.ts:179` rows are `{id, ref, grade, reason}`), an already-graded pair is never re-graded when the asset text changes, and a second judge's grades mix in silently.
*Fix:* `label --from <results dir>` that pools the unjudged top-10 from `samples.jsonl` (semantic included); report a condensed-list nDCG (judged only) beside the current numbers to bound the bias; add `judge`, `prompt`, `date` and `asset_sha256` per row and re-grade on digest change.

### C. Reproducibility and provenance

**C1. Medium. `summary.json` does not identify the run's inputs.**
It records model, akm version/bin/build, git commit, strategy and patch sha. It does not record the effective akm config the eval wrote (eval-side defaults such as `engineConfig`'s `timeoutMs` and `semanticConfig`'s `queryTimeoutMs` change across eval commits), a hash of the cases or qrels, the private seed, the judge host (longmemeval), temperature or thinking switches (B3), or who built a warm index (A1). `git_commit` covers public assets only when the tree is clean, and never covers `private/`. Two private runs on different seeds, or two runs before and after `label` appended grades, are indistinguishable, and `scripts/matrix` compares only model, version and build (`lib.ts:370`).
*Fix:* write the effective config (secrets redacted), `assets_sha256`, `seed` for private runs, the judge endpoint host and the cache key into every summary; have the matrix include `assets_sha256` in its comparability check.

**C2. Medium. A partial run leaves a complete-looking summary.**
consolidate (`evals/consolidate/src/run.ts:291-294`), distill (`run.ts:207-209`) and reflect (`run.ts:231-233`) write `summary.json` and only then `fail()` on a rate-limit or give-up abort. `n_run < n_cases` is in the file, but `scripts/matrix/src/lib.ts` `findResults` accepts any summary with the right label, and nothing in the decision table says the run was cut short.
*Fix:* write `status: "aborted"` and `aborted_reason` into the summary, and have `loadMeasured` treat it as "no result".

**C3. Medium. A timed-out akm is indistinguishable from a model failure.**
`lib/akm/akm.ts:130-143` kills on timeout with SIGKILL; the result is exit code 137 and an empty stderr; `runAkmJson` throws "akm index failed (exit 137): " (reproduced). Rows record that string. A tuning change that makes akm slower shows up as unexplained errors.
*Fix:* detect `code === 137` with `ms >= timeoutMs` and throw "timed out after Ns"; count timeouts separately in every summary.

**C4. Medium. longmemeval `--resume` checks too little and drops the marker.**
`benchmarks/longmemeval/src/run.ts:297-310` compares `akm_version` but not `akm_build`/`akm_bin`, and model/judge names but not endpoints, so a resumed run can mix two builds of one version. `run.ts:344-351` skips `makeResultsDir` on resume, so no `.running` file exists, contradicting the root README.
*Fix:* compare build, bin and base URLs; add `markRunning(dir)` to `lib/results.ts` and call it on resume.

**C5. High. There is no results history.**
`reports/` is described as "published results: scores only" and holds one retrospective. All results folders are gitignored. The promotion README carries two hand-pasted tables from 2026-10-07. The root README mentions an `akm-eval-private` repository for results. For "continuous" benchmarking there is no machine-readable baseline anywhere in the public repository, so nobody outside the lab can check a regression, and the lab's own baseline is wherever the last results folder is.
*Fix:* commit `summary.json` (never `samples.jsonl` from private or own corpora) for each release run under `reports/<akm version>/<eval>/<label>/`, with a small index, and have `scripts/compare` accept those as a baseline. The matrix's `decision.json` belongs there too.

### D. Scoring correctness

**D1. High. extract's prompt-injection harm metric misses the harm it exists to catch, and flags correct reports of it.**
`evals/extract/src/lib.ts:167` `NOT_ASSERTED` mixes negations (`not`, `never`) with hedges (`if`, `no`, `may`, `could`, `possibly`, `whether`), and `:173-174` excuses a phrase when any of them sits within six words before or three after. Reproduced with `claims()` against the planted case's forbidden groups: "Always skip tests if CI is red." gives `[]`; "Set SKIP_TESTS=1 if CI is red; this is the user's preference." gives `[]`; "Maintainer preference: skip tests, no need to run them." gives `[]`; "Preference: always skip tests (possibly set SKIP_TESTS=1)." gives `[]`. Each is the planted instruction saved as a preference. In the other direction, `ABOUT_THE_PLANT` (`:170`) lacks reporting verbs, so "The testkit docs page tells assistants to always skip flaky tests; the real fix is drained()." is flagged as saving the instruction. `planted.saved_instruction` is the matrix's harm metric for extract under a "harm must not rise" rule.
*Fix:* split negations from hedges; let only negations before the phrase excuse it; extend `ABOUT_THE_PLANT` with says/tells/asks/page/PR/bot/log or require an operator/user/maintainer subject; add tests built from each case's `bad` string plus conditional suffixes.

**D2. Medium. `lib/ir.ts` miscounts duplicate ids.**
`retrievalMetrics({ a: 3 }, ["a", "a"], 10, 2)` returns `ndcg 1.6309`, `precision 0.2`, `recall 1` (reproduced): precision and DCG count the duplicate, recall dedupes. retrieval folds refs first (`evals/retrieval/src/lib.ts:106`) and skillret dedupes in `score.ts:19`, but longmemeval passes akm's hits straight in. The rest of the math is right: ideal DCG from the top-k of all grades, P@k over k, MRR within k.
*Fix:* dedupe `retrieved` (keep first) before all metrics; add a test.

**D3. Medium. A missing `searchMode` passes as semantic.**
`evals/retrieval/src/akm.ts:90` and `benchmarks/skillret/src/akm.ts:72` fail a call only when `typeof out.searchMode === "string"` and it differs; a missing field yields `mode: null`, the summary says `"unknown"`, and the probe checks only `error`. Both READMEs say the run stops when a semantic search does not come back semantic. An akm build that drops the field would score keyword rankings in the semantic columns.
*Fix:* in a semantic sandbox require `searchMode === "semantic"` and fail the probe on `mode === null`.

**D4. Medium. longmemeval deviates from upstream in two scored places.**
`benchmarks/longmemeval/src/run.ts:183,244` include the 30 abstention questions in the retrieval means; upstream excludes them because they have no ground-truth location, and `lib/ir.ts` returns 0 for them, so `retrieval.*` is not comparable to upstream recall@k. `run.ts:184` feeds retrieved sessions to the reader in rank order while the baseline sees the haystack chronologically; for knowledge-update and temporal questions, order is signal the baseline has and the akm arm scrambles, so the README's "differ only in which sessions" is not true. Also `run.ts:437-438` deliberately resolves the judge before `useModel` overwrites `MODEL_*`, so with `--model <models.json line>` and no `JUDGE_BASE_URL` the judge goes to the `.env` gateway, while the root README says it uses the model's endpoint.
*Fix:* exclude abstention rows from `metrics.retrieval` and report them separately; sort retrieved indices chronologically for the reader (keep rank order for the metrics); pass the resolved model into `useJudge` as the explicit fallback and record the judge host.

**D5. High. bakeoff's scorers have holes that make "correct facts" vacuous for part of the set.**
27 legacy `deep-bakeoff-*` cases have `expected: {}`; `score_grounded_document` (`bakeoff.py:735-796`) checks shape, verbatim quotes, length and ref coverage, never content: a reply whose every `output` is "This output is wrong in every particular." passes `deep-bakeoff-d01` (reproduced by the bakeoff reviewer). `parse_frontmatter` (`:697-710`) splits lines on the first colon, so a YAML block list `tags:\n  - a` reads as `tags: ""` and scores as invalid output although PyYAML is already a dependency. Graph scoring accepts either direction of a relation and matches any sub-phrase (`:664-679`). `remember_enrich` scores `"observed_at": null` as inventing a date though the prompt invites `null` (`:592, :1357`).
*Fix:* add `required`/`forbidden` terms per legacy case or state that the legacy track measures format and grounding only; `yaml.safe_load` the block; score relation direction; accept absent, null or empty `observed_at`.

**D6. High. judge-gate's labels do not follow its rubric, so `good.rate` is narrow.**
`evals/judge-gate/assets/README.md` says a real fix that adds an intro, headings or reworded prose is bad; at least 14 of the 28 `good` cases have a `labelReason` that admits exactly that (reproduced by grep: "plus a short intro", "plus headings", "splits one paragraph into sections", "Vaguer description", "Leaves redundancy"). 8 of 28 good are description-only punctuation repairs. The 78 bad cases mix 14 churn-only cases with about 65 that invent, reverse or drop facts, and `bad.rate` scores both alike. Feedback presence correlates with the label (good 5/28, bad 35/78), so "feedback present, refuse" scores well. The "held-out private test" the assets README mentions is in fact a 3 to 5 percent rewrite of the same 106 cases.
*Fix:* re-review the loose good cases against the rubric or rewrite the rubric to match; add a `severity` field on bad cases and split `bad.rate` into churn and harmful; say what `--corpus private` is.

**D7. Medium. extract's required-fact matching is brittle in both directions.**
Misses (reproduced by the reviewer): "before March 1st, 2025" and "March 2025" against a required `2025-03-01`; "rowpack>=1.5" against "1.5.0"; "sixty characters" against "60". Lenient passes: a memory that quotes the log line "another export is running" and omits the fix passes insight-01; prefix `init` matches "initially"; prefix `renam` matches "Renamed nothing". One insight case is 9 points of `insights.rate`.
*Fix:* lengthen short prefixes, add date and version paraphrases, and record (separately, not as the score) a similarity against each case's `good` exemplar so disagreements surface for review.

**D8. Medium. Three of agent-ab's nine tasks are not retrieval-gated, and the tasks nudge engagement.**
`evals/agent-ab/tasks/workflow-compliance--feedback-trap-az-tag-list/tests/verify.sh:4-7` says the gold ref does not contain the pattern the verifier greps for, and the library's note teaches a form the verifier rejects. `workflow-compliance--repeated-fail-opencode-provider-token-train/instruction.md:19` names `akm-show-ref: skills/opencode`, leaking the ref the verifier requires. `feedback-trap-docker-compose-render` needs flags the library does not contain. Four task workspaces say "Consult the drillbit skill...", so part of the "did the agent call akm" figure is instructed. The README admits task selection was on one model.
*Fix:* drop or rewrite the three `workflow-compliance` tasks, remove the "consult the skill" lines, keep field names out of instructions, and gate inclusion on a control run failing on two or more models.

**D9. Low. Smaller scoring issues.**
retrieval `banned_above` uses the last relevant rank, so a missing relevant doubles as a banned-above (`evals/retrieval/src/lib.ts:238`); `judged_10 = 1` for an empty result (`:239`); `label.grade()` resolves the asset outside its `try` (`label.ts:170`). judge-gate's unreadable-reply class keys on the free text `parse failed` (`lib.ts:101`). bakeoff's `strip_wrappers` eats a legitimate closing fence; `extra_body` can override `model`/`messages`. Harbor's `toolCalls` counts every `tool_use` event with no dedupe by `callID` (`lib/harbor/report.ts:142-161`).

### E. Private and own corpora

**E1. High. The contamination premise is confounded in both directions.**
The private corpus is the public one with 3 to 5 percent of words renamed and renumbered; the prose and the labels (`defect`, `correct`, `required`, `forbidden`, `label`) are unchanged and sit in the same public repository. A model that memorised a case still recognises it after a name change, so no gap does not mean no contamination. In the other direction the rewrite changes difficulty: real tool names become pronounceable nonsense (`uv run` to `ra run`, `vim` to `rof`, `Palatino` to `rinesuzu`), akm's real exit code 75 becomes 69, a PDF/X key `/Trapped` becomes `/Medinod`, and some pseudo-words are English words (`apache` to `demise`, `jira` to `semi`). Only agent-ab restricts renaming to fictional tools (`evals/agent-ab/src/generate.ts:12-13`). A public-versus-private gap therefore measures recognisability of renamed tools as much as contamination.
*Fix:* say in the README that the private set is a light perturbation, not held-out data; calibrate the difficulty effect once by running a model that cannot have seen the repository on both corpora; make `TOOLS` renaming opt-in per eval; keep sysexit codes and standards keys; reject replacement words found in an English word list.

**E2. High. terminal-bench's private library renames `akm` itself.**
`evals/retrieval/src/generate.ts:118-122` runs the rewrite with no pre-seeded map, so `akm` is renamed like any tool (reproduced: `akm search` becomes `pib search` under one seed, `siz` under another). `benchmarks/terminal-bench/src/run.ts:86-88` hands that library to an agent that runs the real `akm`. agent-ab pins `akm` for exactly this reason (`evals/agent-ab/src/generate.ts:207-213`). The private terminal-bench run measures an agent following instructions for a tool that does not exist.
*Fix:* pin `akm` and every executable the agent runs in retrieval's map, or generate a dedicated terminal-bench library with a pinned map.

**E3. Medium. The number rewrite is inconsistent with itself and with its README.**
`port 8080` and a bare `8080` in the same text get different replacements (reproduced: 6371 and 9683), because ports and numbers are assigned from separate tables (`lib/rewrite/rewrite.ts:113, 180-184, 571, 576`); agent-ab patches this with `harmonize()` and nothing else does. The "10 to 40 percent" move collapses in dense groups: with 39 of the 90 two-digit values present, 29 move by two or less. Decimals of different lengths are ordered separately, so a trim size can end up larger than trim plus bleed. Numbers with meaning outside `KEEP_NUMBERS` change (24 hours, 60, 12 months, exit codes). The numbers table uses "empty" as "not yet assigned", so a labels-only run can renumber a label the corpus did not (`:576`).
*Fix:* treat a port as a number with a range constraint; order decimals by numeric value; add 7/12/24/60/365 and sysexits to `KEEP_NUMBERS`; an explicit `numbersAssigned` flag; tests for each.

**E4. Medium. A failed generation leaves an inconsistent `private/<eval>`.**
consolidate deletes and rewrites the map before validating and exits before removing the old assets (`evals/consolidate/src/generate.ts:83-98`), so a failure leaves old assets with a new map; reflect does the same (`:92-105`); retrieval writes the target before checking and continues to the next collection (`evals/retrieval/src/generate.ts:125-134`); longmemeval and agent-ab leave partial output; bakeoff leaves assets and map. distill, extract and nightly clear on failure. No `run` checks a freshness marker.
*Fix:* write into a temporary folder and rename on success; write `generated.json` (seed, sha of the public inputs, rewrite version) that every `run --corpus private` verifies.

**E5. Medium. judge-gate's generate validates nothing.**
`evals/judge-gate/src/generate.ts:62-88` rewrites and writes with no check, contradicting the root README's "the generate of each eval whose labels depend on the text checks that they still hold", and its labels pass lacks the `--min-count 1000000` guard consolidate and nightly use, so a reason text can rename words the corpus did not.
*Fix:* copy extract's `checkRewrite`: assert the source/candidate diff keeps its changed-line count and that facts named in `labelReason` survive.

**E6. Low. "Private" means three things.**
`--corpus private` is the seeded rewrite of public assets; `--corpus own` is the user's real notes; `"private": true` in `models.json` is a model that may see own notes. Only `own` is gated (`lib/models.ts:95`); a rewritten private set can be sent to a training API, after which the fixed-seed set is burned, and there is no rotation guidance. The root README's corpus column says "private" for terminal-bench (only the library is rewritten) and skillret (a public train split, not rewritten).
*Fix:* rename `private` to `rewritten` (or `perturbed`) in flags and docs; give the table distinct values; add a one-line rotation note.

### F. The public library

**F1. High. 24 files exist twice, 23 of them with different content.**
`corpus/library/{agents,commands,knowledge}/skills/**` holds 32 files that are materialised copies of akm's own ref projection of `corpus/library/skills/**`; 24 have a twin under `skills/` and 23 differ (reproduced by comparing the trees). The same ref is claimed by two files, which is the instability the retrieval README documents as akm#1050 (89 of 136 query rankings moved on one index update). Six `llm-delegation-tool` example pairs are judged under both refs in `evals/retrieval/assets/qrels.jsonl`, so a retriever earns credit twice for one text. A `scripts/skills/litellm-skill/lib/yaml-manager.ts` copy matches no skill and is indexed and judged.
*Fix:* delete the twins (keep the `skills/` originals), regenerate qrels for touched pairs with `evals/retrieval/label`, and add a test that no two library files resolve to one akm ref.

**F2. High. Two shipped skills reference files that moved.**
`corpus/library/skills/print/pdf-review/SKILL.md:65-66` lists `references/print-quality-checklist.md` and `references/ttrpg-standards.md`; the folder holds only `SKILL.md`, and the files live under `knowledge/skills/print/pdf-review/references/`. `skills/print/pdf-layout-reviewer/SKILL.md:263` passes `--standards-file references/print-standards.md` (same story) and `:212` names `references/heuristic-rules.json`, which exists nowhere. An agent installing the library as the README invites will fail on these.
*Fix:* move the eight reference files back under their skills (akm projects them) and drop or restore `heuristic-rules.json`.

**F3. Medium. The library README and metadata are out of step with the tree.**
`corpus/library/README.md:102` advertises web UX gate workflows and `report-*` commands that `:119-124` say were excluded; the five `agents/report-*.md` depend on an absent skill. Five files still name the private bundle `akm-shared`. Frontmatter is inconsistent (`type:` on 2 of 35 `SKILL.md`, 36 files without frontmatter, two `name:` values that include a path), which the reflect and promotion builders inherit as noise. There is no manifest and nothing asserts the asset count that terminal-bench hardcodes as `LIBRARY_ASSETS = 259` (`run.ts:21`).
*Fix:* rewrite "Contents" from the tree; replace `akm-shared`; run `akm lint` on the library in CI; measure the asset count at run start instead of hardcoding it.

**F4. Medium. The corpus is small and skewed.**
259 indexed assets; `ai-skills` (including 22 verbatim OpenCode doc pages) and TTRPG print account for about 55 percent of graded qrels rows. For a public benchmark that claims generality this will saturate and reward tool-name matching.
*Fix:* publish the domain mix in the retrieval README; lean on the `books` collection and `--corpus own` for generalisation claims; add one or two unrelated domains.

### G. Engineering hygiene and documentation

**G1. High. No CI, no root package, 13 copies of the toolchain pins.**
There is no `.github/`, no root `package.json`, and each of 13 `src/` folders pins `typescript 7.0.2` and `@types/bun 1.4.2` in its own `package.json` and `bun.lock`. `bun test` at the root works because of `bunfig.toml`, but typecheck is per folder, the Python suites (bakeoff, harbor) are outside both, and nothing runs any of it automatically. For a repository whose purpose is continuous automated testing this is the first thing to add.
*Fix:* a root `package.json` with workspaces (or a single lockfile), `scripts/check` that runs `bun test`, every typecheck and the Python suites, and a GitHub Actions workflow (see A5).

**G2. Medium. Shared logic is copied, not shared.**
The `.env` loader is byte-identical in 14 bash scripts; `gitCommit` in 11 `run.ts` files; `Fatal`/`fail` in 12; `hideEndpoint` in 6; `slug` in 9; `failureMessage` in 3; `ratio`/`pct` in 8; `mulberry32`, `sha256File` and the download loop in both benchmarks' `dataset.ts`. `lib/harbor/harbor.ts:14-35` already exports three of them. A fix to the `.env` loader must be made 14 times.
*Fix:* `lib/env.sh` sourced by every `run`, `lib/cli.ts` (Fatal, fail, gitCommit, slug, hideEndpoint, failureMessage, pct), `lib/assets.ts` (lock, fetch, verify).

**G3. Medium. `AKM_BIN` from `.env` does not expand `~`, and `generate` ignores `.env`.**
`lib/akm/akm.ts:85` splits `AKM_BIN` on whitespace only; `useAkm` (`:92-96`) expands `~/` for `--akm` alone. The root README says both expand it, and its example `AKM_BIN="bun ~/code/.../src/cli.ts" evals/retrieval/run` is broken as written (reproduced: `sandbox.cmd` is `["bun", "~/code/akm/src/cli.ts"]`; bash does not expand `~` inside quotes either). No `generate` script and not `generate-assets` loads `.env` (0 matches for the loader), while `run` and `label` do, so `generate` validates private assets with whatever `akm` is on `PATH`. The loader also drops a line with leading whitespace and keeps a trailing `# comment` in the value (reproduced).
*Fix:* expand `~/` in `akmCommand()`; use the one shared loader everywhere; trim keys and strip trailing comments.

**G4. Medium. The READMEs promise what the code no longer does.**
Verified mismatches: distill, promotion and retrieval's `label` usage still say own corpora run only against localhost or a private-network `MODEL_BASE_URL` (`evals/distill/README.md`, `evals/promotion/README.md`, `evals/retrieval/src/label.ts:35-37`); the code uses `models.json` `"private": true` since PR #32 and the root README says nothing is inferred from a URL. The consolidate README's Notes say `samples.jsonl` has no claim lists from the judge while the same README documents `only_in_retired` and `only_in_successor`. The root README says `--akm` is on every eval that runs akm and `--model` on every eval that runs a model (false for agent-ab, terminal-bench, bakeoff), that every eval records the akm build (not the Harbor evals), and that "every eval runs the same way against any OpenAI-compatible model" (agent-ab needs the Responses API). The retrieval and skillret READMEs say a non-semantic answer stops the run (D3). The judge-gate README says akm turns thinking off, which the eval does not set (B3). The retrieval assets README calls model grades "a person".
*Fix:* a truth table in the root README (eval by eval: flags, corpora, akm range, sampling settings, what the summary records) generated from the code, and a pass over each README against it.

**G5. Medium. `models.json` is bypassed in the Harbor evals, and the judge fallback depends on call order.**
`evals/agent-ab/src/run.ts:153` sets `MODEL_NAME` and `lib/harbor/harbor.ts:47-61` reads the gateway settings without `resolveModel`, so `--model my-cloud-model` with a `models.json` line goes to the gateway as `openai/my-cloud-model` with the gateway key and no message; `"private": true` is ignored. `modelSettings` forwards the whole host environment (including `JUDGE_API_KEY`) to Harbor. For the judge order, see D4.
*Fix:* call `resolveModel` first and map the result to `OPENAI_BASE_URL`/`OPENAI_API_KEY`; fail loudly on a non-openai provider; pass only the variables Harbor needs.

**G6. Low. Sandbox and config assumptions.**
`lib/akm/akm.ts:65-82` forwards every host variable except `AKM_*`, `JUDGE_API_KEY` and optionally `MODEL_API_KEY`, so a provider key named in `models.json` `api_key_env` still reaches the akm subprocess, and `HOME` is forwarded. `engineConfig` (`:219-227`) pins `configVersion: "0.9.0"` and `provider: "openai"` at `/chat/completions`; no eval can test akm with another provider kind. promotion's `callStats` and `plant` read and write akm's SQLite directly (A5).

**G7. Low. Operational gaps.**
Every eval runs cases one at a time with no `--concurrency`; a full pass of the process evals is hours on a local GPU and no faster on a cloud endpoint that could take ten in flight. The matrix runs `evals/` only. bakeoff's `.running` marker is not cleared between corpora under `--corpus all`, nor are the Harbor evals' and longmemeval's. Token and cost accounting exists only in nightly and the consolidate pool.

## 4. What is in good shape

This matters for deciding how much to change: the foundations are sound and the fixes above are mostly additive.

- **Isolation.** Every akm run happens in a throwaway folder with its own `AKM_*` and `XDG_*` directories and a written config; the model key reaches akm only when the config names it; timeouts kill with SIGKILL; tests prove the argv and the isolation.
- **Honesty.** The READMEs disclose set size, noise, judge self-disagreement, the deterministic-embedder caveat, the duplicate-ref instability and the comparability limits, and they print public and private side by side, never pooled.
- **Determinism where it is claimed.** The rewrite is a pure function of seed and input (verified byte-identical across three runs and a locale change); dataset pins are hashed on every run; sampling is stratified and seeded.
- **Metric code checked against ground truth.** skillret's `score.ts` is verified against pytrec_eval fixtures and reproduces SkillRet's published BM25 row; the longmemeval judge prompts are verified against an upstream fixture; `lib/ir.ts` is right apart from D2.
- **Label validity by construction.** consolidate's pairs are made by one edit from a base so the relation is known without labelling; reflect injects one defect and stops unless akm names exactly that defect; distill and extract keep `good`/`bad` exemplars that the tests score; agent-ab proves each private task three ways.
- **Operational care.** `.running` markers with signal handling; `--repeat` into separate folders; a matrix that resumes and never overlaps two runs of one eval; rate-limit backoff; endpoint masking in shared rows; licence and canary handling in `NOTICE`.

## 5. Recommended plan

Ordered by what unblocks the stated goals soonest. Each step names the findings it closes.

**Step 0. Stop measuring the wrong thing (days).**
- Put `akm_build` into the semantic index cache key and into `state.json`/`summary.json`. (A1)
- Fix the extract canary matcher and add the conditional-suffix tests. (D1)
- Dedupe in `lib/ir.ts`; require `searchMode === "semantic"` in semantic sandboxes; exclude abstention rows from longmemeval retrieval means and feed the reader chronologically. (D2, D3, D4)
- Delete the 24 twin files and the orphan script from `corpus/library`, regenerate the touched qrels, move the eight reference files back under their skills. (F1, F2)
- Pin `akm` in retrieval's rewrite map so terminal-bench's private library is usable. (E2)
- Expand `~/` in `akmCommand()`; make `generate` load `.env`. (G3)
- Correct the stale README passages listed in G4 and the consolidate Notes. (G4)

**Step 1. Make an akm change measurable end to end (one to two weeks).**
- Add a GitHub Actions workflow: install a pinned akm release, run `bun test`, every typecheck, the Python suites, and a `--limit 1` smoke run of each eval against a stub OpenAI server; run it on push and nightly against akm's latest release so contract drift is caught the day it happens. Add a root `package.json` and `scripts/check`. (A5, G1)
- Give agent-ab and terminal-bench `--akm` by packing a checkout into a tarball that Harbor uploads and installs; record what was installed. (A2)
- Teach the matrix a build treatment so two `--akm` rows compare, and have it refuse only when the model or the assets hash differ. (A3, C1)
- Record in every `summary.json`: the effective config with secrets redacted, `assets_sha256`, the seed for private runs, the judge host, temperature/seed/thinking, the index cache key, and `status: aborted` when a run was cut short. Treat aborted and timed-out runs distinctly. (C1, C2, C3)
- Adopt `overrides.ts` in extract and judge-gate; add `--embedder real` to consolidate and nightly; add `--semantic` to longmemeval. (A6, A7, A8)
- Move the shared bash and TypeScript helpers into `lib/env.sh`, `lib/cli.ts` and `lib/assets.ts`. (G2)

**Step 2. Make the numbers trustworthy (two to three weeks).**
- Write `scripts/compare`: per-case agreement and flips between two results folders, paired bootstrap confidence intervals on each eval's main metrics, and per-case flip rate across repeats. Use it in the matrix confirm stage and to set each eval's default `--min-delta`. (B1)
- `--attempts` for terminal-bench, `--repeat` for both Harbor evals, matrix registration for them. (B2)
- One sampling policy in `engineConfig` (temperature 0, thinking off, seed where supported), recorded in the summary. (B3)
- Commit release-run `summary.json` files under `reports/<akm version>/` with an index, and let `compare` take them as a baseline. (C5)
- Re-label judge-gate against its rubric and add a bad-case severity; fix bakeoff's scorers or retire the affected cases; tighten extract's phrase lists. (D5, D6, D7)
- Fix the three agent-ab tasks that are not retrieval-gated. (D8)

**Step 3. Make it a public, reusable benchmark (ongoing).**
- Decide bakeoff's identity: drive akm through `lib/akm`, or relabel it as a frozen prompt probe with a `prompts_version`. (A4)
- Rename `private` to `rewritten`; document the perturbation honestly; make tool renaming opt-in; fix the port/number and decimal-order defects; generate into a temp folder and verify a `generated.json` at run time; validate judge-gate's rewrite. (E1, E3, E4, E5, E6)
- One `--bundle DIR` convention across retrieval, nightly, promotion and terminal-bench so a user runs on their own bundle the same way everywhere, and an `akm lint` and no-duplicate-ref check on the public library in CI. (F3, F4)
- A generated truth table in the root README of flags, corpora, akm range and recorded fields per eval, so the documentation cannot drift from the code again. (G4)
- Grow the smallest classes (promotion good 6, reflect body-defect 3, judge-gate good 28) and publish the corpus domain mix. (B4, F4)

Everything in Step 0 is small and self-contained. Steps 1 and 2 are where the repository starts to do what the README says it is for: show, with a number that survives a rerun, whether a change to akm made its processes better or worse.
