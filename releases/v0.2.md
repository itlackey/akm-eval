The first release of akm-eval. Every run made with it records version 0.2 for the collector and the scorer of every eval, in the manifest of its `summary.json`.

## What it brings

A run is split into three parts, so each kind of change invalidates only what it affects:
- **A scorer fix or a relabelled case** invalidates no run. Stored runs are scored again from their raw outputs (`scripts/rescore`), and `scripts/compare` and the matrix do this by themselves.
- **A changed case** is left out of a comparison and named.
- **A change to what akm is asked** (the collector) raises that eval's collector version. CI fails until the version is raised, and comparisons refuse two collector versions unless the collector is the treatment.

Versions are `MAJOR.MINOR`. A later release changes no version by itself: a part changes version only when its files change, so runs of two releases compare wherever their parts are the same.

README.md, "How results stay comparable", has the rules, and MEASUREMENT_CHANGELOG.md lists, eval by eval, what changed against results made before this release. Those older results compare only as exploratory.

## After upgrading

- Regenerate private or custom test sets made before this release: `./generate-assets`. Every generator now records a digest of its own code, and a run refuses a set made by other code.
- The first matrix run re-runs some rows once, because the matrix now counts cases by their inputs.
