# Run, record and compare

Eval commands run once by default and save quality and performance results.
Comparison reads two saved runs. There is no special baseline or required repeat
count, and no automatic rerun after a checkout or configuration change.

## Changes

- Remove matrix scheduling, screen/confirm stages, saved scheduler state,
  treatment axes, automatic rescoring, repeat-set statistics and winner verdicts.
- Keep every eval, benchmark, mode, case set, fixture and native paired control.
  Existing `--repeat`, task attempts and benchmark-specific resume remain.
- `scripts/compare/run A B [--json FILE] [--md FILE]` displays stored metrics and
  settings. Exact eval/scoring versions and selected inputs must match. Unequal
  scoring/timing coverage suppresses affected deltas, with explanations.
- Explicit `scripts/rescore/run` creates a derived folder, verifies unchanged
  inputs, records current scoring version and preserves collection identity.
- Save `wall_seconds` per completed run. Expose model-call means, request duration
  and tokens/second in the public ledger, preserving unknown values and units.
- Preserve the fwdslsh theme, filtering, sorting, field chooser, exports and all
  published result rows. Remove unused latest-group and variation calculations.
- Keep fixture data and collector/scorer tests. Replace obsolete scheduler and
  statistical-verdict assertions with saved-run comparison regression tests.
- Preserve the `.env` precedence fix: nonempty file values override the shell;
  blank file values retain shell values.

## Migrate

1. Replace each matrix row with its eval's direct `run` command and the same
   model/config flags. Give it a readable `--label`. Run only the configurations
   you need; there is no screen/confirm sequence.
2. Reuse completed saved runs with matching eval version and exact inputs. Add
   `--repeat N` only when you need more observations. Old repeat folders remain
   usable individually; old matrix state and decision files are not inputs.
3. Compare two result folders without `--treatment`, `--repeats` or `--against`.
   Use the public ledger for sorting, filtering and exporting many runs.
4. To update scoring, explicitly rescore both inputs, then compare the resulting
   folders. A changed input set requires new collection. Existing artifacts are
   never rewritten; historical commands belong to their tagged checkout.

No new measurement versions are needed for these reporting changes. Future
input, protocol, label or scoring changes must bump the affected eval's version.
The CLI checks exact case identities as well, including historical 0.5 expansions
that did not bump their versions. This release does not require expensive model
runs or universal baseline/repeat collection.
