# One driver, explicit settings, a Docker runner

Every process eval now runs on one driver with the same flags, a banner of its
effective settings and a check of the model endpoint before the first case.
Semantic search is an explicit `--semantic` flag everywhere, and nothing falls
back to keyword search silently. A prebuilt Docker image runs every eval with
no other install. Measurement versions changed for reflect, LongMemEval,
agent-ab and terminal-bench; read [MEASUREMENT_CHANGELOG.md](../MEASUREMENT_CHANGELOG.md)
before comparing with a 0.6 run.

## What changed

- **One driver for the process evals.** reflect, distill, extract, judge-gate,
  promotion, bakeoff, consolidate and nightly run on `lib/run.ts`: flags, setup,
  the pool of workers, the give-up rule (five errored cases in a row) and the
  summary are written once. What each eval asks akm, its cases and its scoring
  are unchanged, so saved runs compare as before.
- **Before the first case.** A banner prints the model and host, provider,
  keyword or semantic search and the embedding model, temperature and thinking,
  strategy, config patch, concurrency, timeout and akm version. One one-token
  request to the endpoint then ends a run with a wrong URL, key or model name
  with exit 2 and no results folder (`AKM_EVAL_NO_PROBE=1` skips it).
- **Explicit settings.**
  - `--semantic` is a plain flag on every eval that searches. A search that
    does not come back semantic is an error, and the process evals record what
    their searches did as `semantic_verification`.
  - `provider` in a `models.json` line, or `MODEL_PROVIDER` in `.env`, sets
    akm's engine provider kind (`openai`, `anthropic`, `gemini`, `groq`,
    `ollama`, `lmstudio`).
  - `chat.temperature` joins LongMemEval's reader and judge settings, and the
    Harbor evals forward `chat.reasoning_effort` to opencode.
- **Performance.** `--concurrency N` and `--timeout-ms N` on every driver eval
  (nightly, promotion and `consolidate --pool` run as one batch and take only
  the timeout). agent-ab gains `--concurrency` (default 4). The Harbor evals keep
  prepared tools in `.cache/harbor-setup/` and restore them in later trials, and
  warn above 8 concurrent trials about Docker's default address pools.
- **Docker runner.** `ghcr.io/itlackey/akm-eval:main` holds every tool, akm,
  Harbor and the embedding model, and keeps configuration, datasets and results
  in a mounted working folder. Its entrypoint copies the image tree only when
  the image revision changes. See "Set up with Docker" in the README.
- **Semantic Harbor runs.** agent-ab and terminal-bench take `--semantic`,
  verify embedding coverage and a real semantic query during setup, and apply
  `models.json` context and output `limits` to both arms equally.
- **Comparison without gates.** `scripts/compare/run A B` shows any two saved
  runs side by side, whatever their manifest, version or status, and the reader
  decides whether they compare. `scripts/rescore/run` applies current scoring to
  saved raw output in a new folder.
- **Ledger.** Filter by several akm versions, *Latest only*, card layout on
  touch screens, filters, columns and sorting kept in the URL, and *Copy link*.
  Discarded results were deleted from `reports/` rather than hidden.
- **Fixes.**
  - Harbor aborts when an arm completed no trial, and Terminal-Bench can resume
    an interrupted job with the same settings.
  - LongMemEval strips judge reasoning before reading the verdict, counts an
    undecidable verdict as a grading error, records `judge_temperature`, refuses
    `--resume` on a live run and removes its sandbox on Ctrl-C.
  - SkillRet is `complete` when every query was asked.
  - A failed nightly writes an aborted summary instead of none.
  - reflect accepts grounded acronym plurals (`PDFs` for `PDF`).
  - A keyless gateway works.
  - `--help` and the banner say what `--timeout-ms` bounds where it is not one
    akm command: akm improve's own budget in nightly and `consolidate --pool`,
    the drain in promotion. Promotion searches semantically with or without
    `--semantic`, and its help says so.
- **Removed.**
  - `--yes` / `-y`: a run prints its destinations and proceeds.
  - consolidate and nightly's `--embedder deterministic|real`: use `--semantic`
    for the real embedder.
  - retrieval's `--semantic on|off|auto`, and SkillRet's choice of semantic
    search by `--limit`.
  - The corpus aliases. `--corpus` takes `public`, `custom` or `all`.
  - `retired/`, the comparison eligibility checks and the ledger's retirement
    list.

## After upgrading

1. **Run `bun install`**, or pull the new image. With Docker, start a new
   working folder: the entrypoint never deletes files, so an old folder keeps
   `retired/`.
2. **Drop removed flags from your scripts.** Delete `--yes` and `-y`. Replace
   `--embedder real` and `--semantic on` with `--semantic`. Delete
   `--embedder deterministic` and `--semantic off`, which were the default.
   Replace `--semantic auto` with `--semantic` where you want semantic search.
   `run --help` is authoritative.
3. **Set the provider** with `provider` or `MODEL_PROVIDER` when your endpoint
   is not openai-compatible.
4. **Before an expensive run,** follow the README's checklist of that name:
   a `--limit 1` run first, then read the banner.
