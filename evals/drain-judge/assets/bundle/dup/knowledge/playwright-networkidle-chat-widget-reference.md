---
description: "Resolve CI timeouts in storefront tests caused by a persistent chat widget polling interval preventing network idle detection."
---

The storefront suite experienced intermittent failures during continuous integration execution. Specifically, the order-history test case would hang indefinitely when utilizing the `page.waitForLoadState('networkidle')` command. Although the DOM content had completely loaded, the underlying network connection remained active due to a support chat component embedded within the shared page layout. This widget initiates a server request at a frequency of once every twenty seconds. Consequently, the network never achieves the idle state required by Playwright’s default five-hundred-millisecond threshold. The test runner consequently waited until the thirty-second limit was reached before aborting. To fix this, the code was refactored to use an explicit assertion instead. The new implementation employs `await expect(page.getByRole('heading', { name: 'Order history' })).toBeVisible()`. This approach checks for the presence of the specific heading element rather than waiting for network silence. The change reduced execution time to approximately two seconds and stabilized the pipeline. Since the chat feature originates from the global layout, all pages inheriting that structure are affected by the same polling behavior, but the test logic itself remains robust without modifying the widget code.
