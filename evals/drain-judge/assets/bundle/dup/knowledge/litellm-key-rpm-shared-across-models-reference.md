---
description: "Resolving 429 errors by separating shared virtual key rate limits for distinct models."
---

The nightly processing pipeline encountered HTTP 429 status codes because the LiteLLM proxy enforced a global rate cap on a single virtual credential. Although the underlying API provider supported higher throughput, the specific key utilized had its `rpm_limit` parameter set to 60. This constraint applied collectively to all models routed through that identifier, causing both the summarization and classification tasks to compete for the same 60 requests per minute allowance. To eliminate these throttling errors, the configuration was updated to assign independent credentials to each service. The classifier now utilizes a distinct key with an `rpm_limit` of 120, while the summarizer retains its original key. Consequently, the batch process retrieves two separate environment variables, `SUMMARIZER_KEY` and `CLASSIFIER_KEY`, ensuring that per-model quotas are managed independently rather than sharing a single budget. Attempting to configure per-model limits directly within the proxy settings was considered but ultimately not implemented for this resolution.
