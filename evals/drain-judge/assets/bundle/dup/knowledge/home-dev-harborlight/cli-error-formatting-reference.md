description: "Documentation for the harborlight CLI's standardized error handling protocol and implementation details."
---

The command-line interface for harborlight mandates a specific protocol for reporting failures. All diagnostic messages sent to standard error must begin with the literal string `harbor: `. Furthermore, the process termination status must reflect the nature of the failure: a value of 1 indicates a runtime fault, while 2 signifies a usage violation. To manage runtime issues, developers should invoke the `fail` utility exported from `src/util/tty.ts`, passing the relevant message and code. For usage violations, such as absent arguments, the default behavior of Commander.js requires modification. This is achieved by calling `.configureOutput` on the application instance to redirect error writing, stripping the initial `error: ` prefix before prepending `harbor: `. Additionally, `.exitOverride` must be configured to intercept the default exit logic, ensuring that any non-zero exit code from Commander is normalized to 2. This approach guarantees uniform error presentation and accurate exit codes across all subcommands, bypassing Commander's native error handling mechanisms entirely.
