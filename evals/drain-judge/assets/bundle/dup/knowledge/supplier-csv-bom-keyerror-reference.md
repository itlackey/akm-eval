---
description: "Resolving CSV import failures caused by UTF-8 BOM in supplier files."
---

The automated inventory update process previously crashed because the vendor's spreadsheet tool appended a byte order mark to the exported data. This invisible character corrupted the header row, causing the Python script to look for a column named `\ufeffsku` instead of the expected `sku`. Consequently, the `csv.DictReader` object failed to locate the key, triggering a `KeyError`. The issue was resolved by changing the file opening mode from `encoding='utf-8'` to `encoding='utf-8-sig'`. This specific encoding automatically strips the leading BOM, ensuring the headers match the code's expectations. Since implementing this fix, the import has executed successfully for three consecutive weeks without error. It is important to note that this problem only impacts the first column of the dataset, as the BOM only appears at the very beginning of the file. Developers should always use `utf-8-sig` when reading CSV files generated by Microsoft Excel or similar applications to prevent similar parsing issues in the future.
