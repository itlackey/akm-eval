---
description: "Resolving Windows Git CRLF conversion issues for Linux container scripts via .gitattributes."
---

When executing shell scripts within a Linux container on a Windows build agent, the deployment process encountered a critical failure. The root cause was the automatic conversion of line endings from LF to CRLF during the repository checkout phase. This transformation resulted in the error message `/bin/bash^M: bad interpreter` when attempting to run `./deploy.sh`. To resolve this, a `.gitattributes` file was introduced to enforce consistent line ending behavior across all platforms. By adding the rule `*.sh text eol=lf`, Git is instructed to preserve LF endings for all shell script files regardless of the operating system performing the checkout. This configuration ensures that the scripts remain compatible with the Linux environment, allowing the packaging job to succeed. It is important to note that the source files in the repository were already correctly formatted with LF endings; the issue stemmed solely from the Windows agent's default behavior during the checkout process. Implementing this attribute file prevents future occurrences of this specific interpreter error.
